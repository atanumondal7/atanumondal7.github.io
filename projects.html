uart.sv4UVMVerified in loopback

UART TX/RX, verified with UVM

The UVM testbench is the real project here. The UART is a parameterized transmitter and a 16x-oversampling receiver, and it gives me something small enough to run my UVM skills on: a driver, a sequencer, two monitors, a scoreboard with a reference model and coverage, plus SystemVerilog assertions on the interface.

It has two modes. In loopback the TX feeds the RX. In bit-bang mode the testbench drives the RX line itself, which injects a bad stop bit to test rx_error and scales the bit period to check the baud-rate tolerance.

My simulator, Questa Starter Edition, has no randomize() or covergroup, so the stimulus uses $urandom_range and the coverage is counted by hand in a uvm_subscriber.

alu_cdv2Constrained-randomComplete

4-bit ALU, my first coverage-driven testbench

This was the first time I touched advanced verification methodology. Constrained-random stimulus, coverage-driven verification and interfaces were all new to me, and I used them together in one testbench for a 4-bit ALU.

A randomizer class holds the random fields, a weighted opcode distribution and a covergroup with cross coverage. A reference model inside the testbench checks every result.

usr_tb3Layered testbenchComplete

Universal shift register testbench

A class-based testbench for a universal shift register. The interesting part was a two-cycle sampling latency caused by clocking-block skew. I fixed it by priming the monitor's edge and adding a two-stage input history buffer.

alarm_clock3Layered testbenchIn progress

Digital alarm clock

A digital alarm clock that I built from a spec sheet with no reference design: seven RTL modules around a controller FSM. The main branch is fully runnable.

The testbench is UVM-style without the UVM library, with a generator, driver, monitor, scoreboard and coverage collector connected by mailboxes. I'm doing it this way so I understand what UVM does underneath. The last two features are being built on a separate branch.
